# 2026-10-06 design refresh

## Users and core task

The primary user is a game developer working in Codex or a desktop game engine.
They describe a game and connect a project, then expect separate usable assets
and an efficient way to inspect results. Most visits need creation, progress and
review rather than manual editing.

The existing production home had a large introduction and Codex installation
banner ahead of its working inputs. Its stage labels did not indicate current
state. The marketing page mixed onboarding with lengthy historical verification
records and an old editor screenshot. These were observed in the local browser
preview before implementation; the Mac desktop was locked.

## One direction

Use a quiet, legible studio: warm paper for the marketing page, dark green ink
for the working app, and mint for selection and primary actions. Use installed
Korean system fonts, generous but controlled spacing, 8–16px radii and 150ms
state transitions. Keep decorative surfaces subtle while giving interactive
boundaries stronger contrast. See [shared tokens](../../packages/ui/src/tokens.css).

The website explains the product and onboarding. The application prioritizes
current work, disabled-action reasons, cancellation, retry and review. It retains
external-transfer consent, local preparation approval and factual provider
limitations.

## Verification

Verification results are appended after implementation. Browser UI checks and
mocked command-boundary regression tests do **not** establish new native platform
or provider support. The Mac app is built and its artifact inspected separately;
GUI execution remains excluded while the Mac is locked. Windows native execution
is outside this request's agreed verification scope.

### Completed checks

- Desktop TypeScript/Vite build and site Vite build: passed. The site source also
  passed a separate TypeScript check. `git diff --check`: passed.
- Production UI: **35/35 passed** in real React/Chromium with mocked desktop
  command boundaries. Covered connection/transfer approval, cancellation,
  delayed responses, per-item retry/review, progress, secret redaction and
  unsupported environments. The existing 390px check verifies readable controls,
  no horizontal overflow and a 3px keyboard focus outline.
- App browser layouts: **1100×720** (configured minimum) and **1500×960**
  (configured default). No horizontal overflow; longer work areas scroll.
  The guide dialog fits the minimum window. Escape closes it and restores focus.
- Website browser layouts: **320×844**, **390×844**, **768×1024** and
  **1440×960**. No horizontal page overflow. Corrected a mobile start-button
  line break and confirmed both introduction buttons have a 50px height at 390px.
  Mac installation details, long commands, copy confirmation and image expansion
  were checked. Escape closes the expanded image and restores focus. No broken
  images remained after the new preview assets loaded.
- Reduced-motion emulation: transitions are `0s` and scrolling is `auto` in both
  interfaces. Temporary browser media/viewport overrides were cleared afterward.
- Tab navigation keeps the production component mounted: the browser confirmed
  the same description-field instance before/after visiting the library. This
  preserves in-progress input state; native typing remains part of the excluded
  GUI check.
- The new share PNG is 1200×630 and uses the repository's actual Blender renders.
  The new production-home JPG is 1500×960 and explicitly shows browser mode.
  README uses the new images; original older screenshots and assets remain.

### Native artifact

The final Mac `.app` built successfully. It is **arm64**, version **0.1.11**, and
passed `codesign --verify --deep --strict` with its existing ad-hoc signing setup.
The three current hashed frontend asset names were verified inside its executable.
The local review copy and detailed hashes are in
`output/design-20261006/Asset Studio.app` and `native-artifact.json`.

At completion of the initial design task this was a local 0.1.11 design build;
no release, updater publication, source push or production deployment had been

production deployment. Mac 0.1.12 packages the design with a new signed updater
and DMG; Windows and standalone CLI/skill downloads retain 0.1.11. See

The Rust toolchain reported an unavailable LLVM helper when attempting to strip
debug information; Cargo still completed the optimized build and the bundle and

Rust-code and Vite chunk-size warnings remain. These checks do not replace
native execution. **Mac GUI execution was skipped because the Mac is locked,
and Windows native execution was not performed.** No new GPT/provider request
or paid API was used for this design verification.
