# Windows 사용 안내

Windows 0.1.8 설치 파일 `AssetStudio_0.1.8_x64-setup.exe`를 실행하세요. 현재 사용자 계정에 설치됩니다. 기존 포터블 사용자는 설치 파일을 한 번 설치하면 이후부터 앱 내부 업데이트를 이용할 수 있습니다. 기존 프로젝트는 그대로 열 수 있습니다.

포터블 ZIP도 제공합니다. 전체를 새 폴더에 풀고 `asset-desktop.exe`를 실행하세요. `examples`와 `workers` 폴더도 함께 두어야 합니다. Node.js·Rust·Visual Studio는 앱 사용에 필요하지 않습니다. Windows WebView2가 필요합니다. 설치 프로그램은 런타임을 자동 다운로드하지 않으므로 WebView2가 없는 PC에서는 Microsoft 공식 경로에서 별도로 준비하세요.

Windows Authenticode 코드 서명은 아직 없습니다. 업데이트 파일에는 별도의 암호학적 서명이 있으며 두 종류의 서명은 다릅니다.

## 화면 읽기와 사용 가이드

주요 버튼과 입력란은 14px 이상, 가이드 본문은 16px로 표시합니다. Windows의 Segoe UI·맑은 고딕을 사용하고 긴 기술 설명은 상세 보기로 접었습니다. 상단 **사용 가이드**에서 가져오기, 편집, 3D 제작, 내보내기, 구독 이미지와 업데이트 순서를 확인하세요. Esc로 닫으면 원래 버튼으로 돌아갑니다.

## 앱 업데이트

앱 시작 시와 10분마다 GitHub 공식 릴리스에서 새 버전을 확인합니다. 업데이트가 있으면 상단에 버전 버튼이 나타납니다. **앱 업데이트** 창에서 버전·출처·다운로드 용량·SHA-256·라이선스를 확인하고 동의한 뒤 **지금 업데이트**를 누르세요. 제작 작업이 진행 중이면 완료를 기다립니다.

다운로드한 설치 파일의 서명·서명에 포함된 버전·파일 크기·SHA-256을 확인한 뒤 설치하고 앱을 다시 실행합니다. 프로젝트와 원본 파일은 보존합니다. 확인 실패 또는 네트워크 오류 시 설치하지 않으며 다음 확인이나 수동 확인을 이용할 수 있습니다. 설치 시작 실패 후에는 앱을 직접 다시 실행하세요.

## 게임 프로젝트에서 제작하기

0.1.8의 시작 화면은 **게임 에셋 제작**입니다. **GPT 구독 연결**에서 계정을 연결하고, **게임 프로젝트 루트 연결**로 기존 게임 폴더를 선택하세요. 게임 설명과 필요한 에셋을 적고 전송 범위를 확인한 뒤 **필요한 에셋 분석**으로 목록을 검토합니다. Windows에서는 개별 2D 이미지를 제작할 수 있습니다. 이미지에서 3D 모델을 추정하는 TripoSR 경로는 현재 Apple Silicon Mac 전용입니다.

완료된 결과는 게임 프로젝트 안의 새 `AssetStudioGenerated/<제작 ID>/` 폴더에 저장합니다. Unity에서는 `Assets/`, Unreal에서는 `Content/` 아래에 만듭니다. 원래 파일과 장면 참조는 덮어쓰지 않습니다. 외부 요청 결과가 불명확하면 자동으로 재요청하지 않습니다. 전송되는 정보와 검수·재시도 방법은 [게임 에셋 제작 안내](game-production.md)를 확인하세요.

## 편집 도구로 첫 에셋 묶음 만들기

시작 화면의 **편집 도구**를 누르면 라이브러리·캔버스·3D 뷰포트·작업 큐를 이용할 수 있습니다.

1. 프로젝트를 만들고 규격의 크기·단위·스타일을 정합니다. 제공 예제는 로컬 샘플이며 AI 생성 결과가 아닙니다.
2. PNG/JPEG/WebP 파일을 가져옵니다. 원본은 보존하고 변환 결과를 새 버전으로 기록합니다.
3. 이미지를 선택해 크기 조정·색상·배경 처리를 실행합니다. 여러 이미지를 선택하면 아틀라스와 좌표 JSON을 만들 수 있습니다.
4. 결과의 검사 상태와 버전을 확인한 뒤 새 폴더로 내보냅니다. 파일과 manifest가 함께 저장됩니다.
5. 앱을 닫고 프로젝트를 다시 열면 에셋·버전·작업 상태를 복원합니다.

## 3D 소품

Blender를 별도로 설치해야 합니다. 앱은 Blender를 자동 다운로드하지 않습니다. 상자·테이블·선반의 치수와 재질을 정하면 GLB, 편집 가능한 `.blend`, 미리보기 이미지를 만듭니다. GLB는 미터·Y-up이며 제조용 CAD 도면이 아닙니다.

가져온 GLB는 **3D 만들기**에서 삼각형 예산과 높이·텍스처 해상도를 정해 새 버전으로 다듬을 수 있습니다. 보존된 고해상도 형상에서 다시 제작하므로 예산을 낮춘 뒤 높일 수 있습니다. 이 경로에는 TripoSR 다운로드가 필요하지 않습니다. [3D 품질과 한계](model-quality.md)를 확인하세요.

## ChatGPT 구독 이미지

앱의 **구독 연결**에서 아래 세 단계를 진행하세요. Codex가 이미 있으면 서명과 버전을 확인해 재사용합니다.

1. **Codex 준비**: Codex가 없는 Windows x64 PC에서는 출처·버전·용량·SHA-256·라이선스를 확인하고 다운로드에 동의하세요. 앱 전용 공간에 준비하며 PATH 변경이나 Node.js·Rust 설치는 필요 없습니다. 진행률을 확인하고 준비를 취소할 수 있습니다.
2. **공식 계정 연결**: 기본 브라우저의 OpenAI 공식 로그인에서 ChatGPT 구독 계정을 연결하세요. 앱에 API 키를 입력하지 않습니다.
3. **연결 확인**: 로그인 후 앱으로 돌아와 버튼을 누르세요. 준비가 확인되면 원하는 이미지를 직접 요청할 수 있습니다.

관리형 준비에 사용하는 공식 배포본은 [Codex 0.160.0 Windows x64 package](https://github.com/openai/codex/releases/tag/rust-v0.160.0)이며 157,444,460 bytes (150.15 MiB)입니다. SHA-256은 `7f7fbbc8d6fd4ea2f3b13855ef47ea59663ba7e61fb2e9821df37163b8030891`, 라이선스는 [Apache-2.0](https://github.com/openai/codex/blob/rust-v0.160.0/LICENSE)와 패키지에 포함된 추가 구성 요소의 고지입니다. SHA-256과 실행 파일의 OpenAI 서명을 확인한 뒤 등록합니다. Mac 준비 방법은 [Mac 설치 안내](macos-quickstart.md)에 있습니다.

이미지 제작의 추론 모델은 GPT-6.1 Sol (`gpt-6.1-sol`)이며 이미지 목표는 GPT Image 2입니다. 제작 목록 분석에는 별도의 텍스트 플래너 GPT-5.5를 사용합니다. 설명과 승인한 스타일·규격이 공식 런타임에 전달되며 구독 한도를 사용할 수 있습니다. API 키 결제로 자동 전환하지 않습니다.

연결 성공과 실제 이미지 생성 성공은 다릅니다. 현재 검증 결과는 [공급자 실증](provider-feasibility.md)을 확인하세요. 원격 결과를 확인하지 못한 작업은 ‘결과 불명’으로 남으며 자동으로 재요청하지 않습니다. 실제 사용 이미지 모델이 응답에 없으면 확인되지 않았다고 표시합니다.

앱에 표시되는 추론 모델 이름과 고정 목록은 계정의 모델 이용 권한을 증명하지 않습니다. 작업을 넣을 때 추론 모델·이미지 목표·런타임 버전을 함께 기록합니다. 이전 모델로 만든 작업은 설정을 변경해 다시 전송하지 않으며, 현재 연결을 확인한 후 별도의 새 요청이 필요합니다. [ima2-gen과의 구조 비교](ima2-gen-comparison.md)도 제공합니다.

0.1.1에서 `native turn completed without an image artifact`가 나왔다면 앱 업데이트에서 최신 버전을 설치하세요. 0.1.2부터 Sol의 이미지 도구 호출에 필요한 공식 호스트 설정을 수정했습니다. 업데이트 후 구독 연결을 다시 확인하고 원하는 이미지를 새로 요청하세요. 기존 실패 기록은 보존하며 업데이트만으로 재전송하지 않습니다. 사용 한도에 도달했다는 오류는 연결 화면의 한도·초기화 시각을 확인하세요.

## 작업과 복구

작업 큐에서 진행·오류를 확인할 수 있습니다. 취소 후 실행 중인 로컬 작업이 종료돼야 재실행하거나 프로젝트를 전환할 수 있습니다. 완료 결과 재사용은 저장된 파일의 해시를 확인하며, 재실행은 새 버전을 만듭니다. 외부 결과 불명 작업을 새 요청으로 보내면 중복 생성될 수 있으므로 기존 결과를 먼저 확인하세요.

다른 Windows PC에서의 실행과 설치·업그레이드·제거 수명주기는 개발 PC의 네이티브 검사와 구분합니다. Mac은 별도의 패키지와 업데이트 채널을 사용합니다. 자세한 상태는 [플랫폼 지원](platform-support.md), 실제 검사 결과는 [검증 기록](verification.md)에 있습니다.
