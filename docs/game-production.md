# 게임 설명과 프로젝트 폴더에서 에셋 제작

Windows 0.1.9와 Mac 0.1.8의 기본 화면은 **게임 에셋 제작**입니다. 게임 설명과 기존 게임 프로젝트 루트 폴더로 제작 목록을 만들고, 항목별로 제작한 뒤 결과를 확인합니다. 두 플랫폼에서 이미지·3D·혼합을 선택할 수 있습니다. 3D는 참고 이미지를 로컬 TripoSR와 Blender로 변환합니다. 편집기는 **편집 도구**에서 따로 열 수 있습니다.

1. **GPT 구독 연결**에서 공식 계정 연결과 연결 상태를 확인합니다.
2. **게임 프로젝트 루트 연결**로 기존 게임 폴더를 선택합니다. Asset Studio 작업 공간은 별도로 유지합니다.
3. 장르, 시점, 플레이 방식, 세계관, 원하는 스타일과 필요한 범위를 설명합니다. 필요하면 **참고 이미지·모델 추가**로 참고 자료를 가져와 최대 5개를 선택합니다.
4. 전송 범위를 확인하고 **필요한 에셋 분석**을 누릅니다. 제작 목록과 누락·제한 사항을 확인합니다.
5. **필요한 에셋 모두 제작**으로 목록 전체를 제출합니다. 완료된 카드에서 결과를 살펴보고 검수 승인합니다. **이 에셋 개선하기**는 선택한 결과를 참고 자료로 넣고 해당 에셋만 새로 제작할 설명을 준비합니다. 실패한 항목은 실패 단계만 다시 실행할 수 있습니다.

예: “3인칭 우주 생존 게임. 사실적인 금속·주황색 발광 스타일로 연료 아이콘, 채집 도구, 광석, 소행성과 기지 소품을 만들어 줘. 기존 프로젝트에 있는 배경과 UI는 유지하고 누락된 소품을 채워 줘.”

## 프로젝트 분석과 전송 범위

폴더 연결은 기존 파일을 읽기만 합니다. Unity·Godot·Unreal 설정으로 엔진을 식별하고 에셋 파일 목록을 정리합니다. Godot의 `res://` 경로와 Unity의 GUID 참조는 제한된 로컬 파서로 누락 여부를 확인합니다. Unreal의 바이너리 에셋 내부 참조, 게임 실행과 엔진 내 가져오기는 검증하지 않습니다. 엔진 미확인 프로젝트도 설명과 파일 목록으로 계획할 수 있습니다.

`.git`, 엔진 캐시, 의존성·빌드 폴더, 자격 증명·숨김 파일과 심볼릭 링크는 분석에서 제외합니다. 소스 코드는 실행하거나 GPT에 전송하지 않습니다. 동의한 요청에는 게임 설명, 에셋의 **상대 파일 이름**, 누락 참조, 직접 선택한 참고 자료의 메타데이터와 이미지 미리보기만 전달합니다. 이미지·GLB 원본은 새 사본으로 가져옵니다.

분석은 파일 20,000개, 기본 에셋 목록 2,000개 등의 한도를 적용하고, GPT에 전달할 목록은 크기에 맞게 제한합니다. 생략된 목록과 확실하지 않은 참조는 경고로 남깁니다. 이 앱이 이전에 전달한 파일도 해시를 확인해 다음 구성안의 에셋 목록에 포함합니다. 프로젝트나 참고 버전이 분석 후 바뀌면 다시 분석해야 합니다.

## 개별 2D·3D 제작

GPT-5.5는 도구를 실행하지 않는 텍스트 플래너입니다. 각 항목은 이름·종류·용도와 그 **에셋 하나만** 묘사하는 설명을 가집니다. GPT Image 2를 목표로 공식 Codex 구독 경로에서 이미지를 요청합니다. 응답이 실제 이미지 모델 ID를 제공하지 않으면 확인 모델은 미확인으로 기록합니다. 유료 API로 대체하지 않습니다.

2D 항목 하나는 이미지 요청·파일 하나입니다. 3D 항목은 GPT의 단일 물체 참고 이미지 → 배경 준비 → **로컬 TripoSR** → Blender의 UV·텍스처·게임용 모델·LOD 제작을 순서대로 처리합니다. 직접 GPT가 3D 메시를 반환하는 경로는 아닙니다. 투명 배경은 유지하고, 균일한 배경은 물체 외부만 자동 분리합니다. 복잡한 배경이나 여러 물체는 자동 통과시키지 않습니다. 준비된 사본은 새 버전으로 남깁니다.

3D 준비에는 Windows x64 또는 Apple Silicon, Blender와 최소 16GB 메모리가 필요합니다. Windows는 Microsoft Visual C++ 2015–2022 x64 런타임이 필요하고, 최초 동의 후 CPython 3.12.10·PyTorch CPU·모델을 약 1.89GiB 내려받습니다. 시스템 Python이나 CUDA는 필요하지 않습니다. Mac은 CPython 3.9와 모델·의존성을 준비합니다. 현재 Tripo Studio의 최신 모델이 아닌 구형 TripoSR이며, 뒷면·미세 형상·재질·토폴로지·스케일은 추정값입니다. 기본 3D 높이는 1m이고 게임 모델 예산은 프로젝트 예산 내 최대 10,000 삼각형입니다. 리깅·애니메이션·음원·코드·CAD·여러 물체 장면은 이 제작 목록에서 완성하지 않습니다.

한 계획은 최대 **120개 시각 에셋**입니다. 범위를 넘거나 지원하지 않는 요구 사항은 계획의 경고에 남깁니다. 파일 목록만으로 게임에 필요한 모든 요소나 정확한 형상을 보장하지 않으므로 계획과 결과를 확인하세요.

## 저장과 재시도

검증된 결과는 게임 프로젝트의 새 제작 폴더에 자동으로 저장합니다.

| 프로젝트 | 새 결과 위치 |
|---|---|
| Unity | `Assets/AssetStudioGenerated/<제작 ID>/` |
| Unreal에 Content 폴더가 있는 경우 | `Content/AssetStudioGenerated/<제작 ID>/` |
| Godot·기타 | `AssetStudioGenerated/<제작 ID>/` |

항목별 새 폴더에 PNG 또는 GLB·LOD·텍스처와 해시가 있는 `manifest.json`을 저장합니다. 고해상도 형상·Blender 원본·미리보기와 작업 이력은 Asset Studio의 로컬 보관함에도 남습니다. 기존 파일과 원래 장면 참조를 덮어쓰지 않습니다. 엔진에서 사용할 결과와 참조 연결은 검수 후 선택하세요. 같은 이름의 사용자 폴더에 앱 표식이 없으면 작성하지 않습니다.

진행 상태는 실제 큐와 파일 검증에서 가져옵니다. 같은 시작 요청은 중복 등록하지 않고, 재실행은 성공한 선행 이미지를 유지합니다. GPT 이미지를 받은 뒤 로컬 저장에 실패한 경우에도 수신 파일을 재사용합니다. 외부 요청 결과가 불명확하면 자동 재전송하지 않습니다. 검수 승인 시 전달 파일의 해시를 다시 확인합니다. 앱을 다시 열면 제작 기록과 검수 상태를 복원합니다.
