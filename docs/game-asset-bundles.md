# 게임 설명으로 개별 에셋 묶음 만들기

게임의 분위기와 필요한 아이템을 설명해 GPT 구독 연결에 텍스트 구성안을 요청하고, 이름과 설명이 있는 개별 행을 검토해 제작하는 흐름입니다. **한 행은 에셋 하나**입니다. 2D 이미지와 고정 레시피의 3D 모델을 함께 구성하고, 포함한 행을 한 번에 작업 큐에 제출합니다.

이 안내는 **Mac 0.1.6 게임 에셋 묶음 기능**을 다룹니다. Mac 네이티브 백엔드에서 GPT-5.5 구성안을 받아 개별 무기 PNG 5장과 GLB 모델 2개를 제작·저장·재열기·독립 내보내기했습니다. 두 모델의 GLB와 `.blend`도 별도 Blender 프로세스에서 다시 열어 치수·UV·재질을 확인했습니다. 다운로드 버전과 설치 안내는 [README](../README.md)의 공개 배포 정보를 따르세요.

## 1. 게임 설명과 출력 구성 정하기

작업대의 **게임 에셋 만들기**을 눌러 **게임 에셋 묶음 구성안**을 엽니다. **게임 설명 · 테마**에 게임 분위기, 필요한 아이템, 용도와 각 에셋의 차이를 적으세요. 예를 들어 “우주 전쟁 게임에서 쓸 무기 5종. 레이저 검, 소총 등 서로 다른 이름과 실루엣이 필요합니다”처럼 설명할 수 있습니다.

**출력 구성**은 다음 중에서 선택합니다.

| 화면의 선택 | 구성안에 들어가는 항목 |
| --- | --- |
| 2D 이미지 | 이미지·스프라이트·텍스처의 개별 PNG 행 |
| 3D 모델 | 고정 레시피로 만드는 새 독립 모델 행 |
| 이미지 + 3D 모델 | 개별 이미지 행과 새 모델 행을 함께 구성 |

**요청 이미지 수 (선택)**는 전체 묶음 수가 아니라 **2D 이미지 행의 정확한 수**입니다. 이미지·스프라이트·텍스처 행을 합쳐 셉니다. 5를 입력하면 최초 구성안에 서로 다른 이름과 개별 설명을 가진 이미지 행 5개를 요청하며, 혼합 구성의 모델 행은 별도로 셉니다. 비워 두면 게임 설명에 맞는 항목 수를 제안합니다. 3D 모델만 선택하면 이 이미지 수 입력란은 표시하지 않습니다.

구성안에서 행을 추가·삭제하거나 포함·제외한 뒤에는 화면의 **이미지 N개 + 모델 M개**가 실제 제출 수입니다. 한 묶음은 이미지 최대 20개, 모델 최대 24개, 전체 행 최대 44개입니다.

## 2. 참고 자료 선택과 전송 동의

**참고 이미지·GLB 가져오기**로 PNG·JPEG·WebP 이미지 또는 검증 가능한 GLB를 프로젝트에 가져옵니다. **현재 선택 N개를 참고 자료로 사용**하거나 목록에서 직접 고를 수 있습니다. 이미지와 모델을 합쳐 **최대 5개**까지 참고 자료로 선택합니다. 파일을 가져온 뒤에도 목록에서 사용할 자료를 선택해야 합니다.

GLB는 자체 포함된 glTF 2.0 파일을 검사합니다. 파일 크기·정점·장면 등 처리 한도를 적용하고, 실제 정점과 인덱스, 장면 변환을 읽어 정점 수·삼각형 수·미터 치수를 측정합니다. 외부 버퍼나 텍스처 파일·URL을 읽는 GLB는 허용하지 않습니다.

선택한 GLB는 **측정한 메시 메타데이터**로 참고합니다. 해당 에셋 버전에 썸네일이 이미 있으면 그 이미지도 참고 자료로 사용할 수 있습니다. 썸네일이 없는 GLB에 새 미리보기를 자동으로 만들어 전송한다고 보장하지 않습니다. 원본 GLB 메시를 코드로 실행하거나, 참고 모델의 임의 형상을 복원·편집하는 기능은 제공하지 않습니다.

참고 자료가 있으면 **선택한 참고 자료의 이미지·미리보기·모델 메시와 치수 메타데이터를 공식 Codex에 전송하는 데 동의합니다**를 확인한 뒤 구성안을 요청합니다. 이 동의는 제작 항목 승인과 별개입니다. 참고 선택이나 활성 버전이 바뀌면 전송 동의와 구성안을 다시 확인합니다. 참고 자료 없이 새 구성안을 요청할 수도 있습니다.

## 3. 텍스트 구성안을 검토하고 수정하기

**구성안 만들기**는 공식 Codex의 GPT 구독 연결에서 **GPT-5.5 (`gpt-5.5`)의 텍스트 응답만 요청**합니다. 공식 카탈로그의 모델을 도구 실행 없는 모드로 지정하며, 구성안에 텍스트 요청 모델을 별도로 표시합니다. 이 단계에서는 이미지나 3D 파일을 제작하지 않습니다. 구성안 작성에도 구독 사용량이 발생할 수 있고, 실제 구성안 수신과 계정의 이용 권한은 별도 확인 대상입니다. 유료 API로 자동 대체하지 않습니다.

| 단계 | 요청 모델·도구 | 역할 |
| --- | --- | --- |
| 텍스트 구성안 | GPT-5.5 · `gpt-5.5` | 이름·설명·용도와 고정 모델 매개변수를 제안하는 텍스트 플래너 |
| 승인 후 개별 이미지 제작 | GPT-6.1 Sol · `gpt-6.1-sol` | 별도 이미지 에이전트로 개별 이미지 생성 요청을 진행 |
| 승인 후 독립 3D 제작 | 로컬 Blender | 승인한 아홉 고정 레시피와 수치 매개변수로 실제 메시·렌더를 제작 |

구성안의 플래너 모델과 이미지 에이전트는 목적이 다릅니다. 실제 이미지 모델의 확인 정보는 이미지 수신 결과에서 따로 확인합니다.

**개별 에셋 구성안 검토**에서 각 행의 **에셋 이름**, **파일 출력**, **에셋 유형**, **개별 에셋 설명**, **게임 안에서의 용도**, **이 항목의 참고 자료**를 수정합니다. 이미지·모델 항목을 추가하거나 삭제할 수 있고, 포함 체크를 끈 행은 제출하지 않습니다. 이름은 서로 구분되게 정하며 **이름 중복 · 파일 이름 정리**로 정리할 수 있습니다.

2D 행마다 해당 이름의 오브젝트 하나를 개별 이미지 파일로 요청합니다. 여러 아이템을 한 이미지에 배치하는 콜라주·연락판·스프라이트 시트 요청과 구분됩니다. 실제 수신 이미지의 내용·크기·투명도·스타일은 결과에서 확인하세요.

### 기존 2D 에셋 개선

**제작 방식 → 기존 2D 에셋 개선 · 새 버전**을 선택하고 개선할 이미지·스프라이트·텍스처를 참고 자료로 고릅니다. 각 행의 **새 버전을 저장할 원본**을 지정하면 해당 에셋에 개선 결과를 새 버전으로 저장합니다. 원본 파일과 이전 버전은 유지합니다. 개선 모드는 2D 대상이며, 3D 모델은 새 독립 에셋으로 제작합니다.

### 독립 3D 모델의 고정 레시피

3D 행의 **모델 레시피**에서 다음 아홉 가지를 선택할 수 있습니다. 설명과 참고 자료는 레시피 선택·검토에 쓰며, 모델 제작은 고정된 로컬 기하 함수와 수치 매개변수로 진행합니다. 생성된 코드를 에셋 입력으로 실행하지 않습니다.

| 화면의 레시피 | 식별자 | 고정된 주요 형태 |
| --- | --- | --- |
| 상자 · 컨테이너 | `crate` | 패널과 프레임 |
| 테이블 | `table` | 상판과 네 다리 |
| 선반 | `shelf` | 측면 프레임과 선반 |
| 검 | `sword` | 칼날·손잡이·가드 |
| 소총 | `rifle` | 몸체·손잡이·총열·개머리판 |
| 우주선 | `spaceship` | 선체·날개·추진부 |
| 배럴 | `barrel` | 각진 원통 몸체와 고리 |
| 바위 | `rock` | 비대칭의 각진 바위 실루엣 |
| 나무 | `tree` | 줄기와 층을 이룬 수관 |

각 행에서 **너비·깊이·높이·베벨 (m)**과 **모델 재질 색상**을 수정합니다. 치수는 0.03~100m, 이 화면의 베벨은 0~0.25m이면서 가장 짧은 치수의 1/4 이하여야 합니다. 기본 재질 색상은 행의 `#RRGGBB` 값을 적용하고 보조색은 승인한 스타일 팔레트를 사용합니다. Blender는 별도로 설치해야 합니다.

모델마다 독립된 GLB, 편집 가능한 `.blend`, 썸네일과 턴테이블을 새 출력 폴더에 저장합니다. GLB는 미터·Y-up, Blender 원본은 미터·Z-up입니다. 고정 소품은 닫힌 솔리드 구성요소를 한 에셋 메시로 조립하며, 제조용 CAD 솔리드를 보장하지 않습니다. Blender는 스크립트 자동 실행을 끄고 실행합니다.

## 4. 포함한 행을 한 번에 큐에 제출하기

공통 규격·스타일과 각 행을 검토한 뒤 제작 기준 승인 체크를 선택하고 **검토한 에셋 묶음 제작**을 누릅니다. 포함한 모든 행을 검증한 뒤 **하나의 요청으로 원자적으로 큐에 등록**합니다. 등록 검증에 실패하면 일부 행만 큐에 넣지 않습니다. 등록 후에는 각 이미지·모델 작업의 상태와 산출물을 따로 확인합니다.

참고 자료 버전, 프로젝트, 규격이나 스타일이 바뀌면 구성안을 다시 작성해야 합니다. 제출한 2D 항목은 각각 별도 구독 요청이며 외부 사용량과 계정 한도가 적용됩니다. 승인과 큐 등록 자체가 실제 파일 수신·제작 완료를 뜻하지는 않습니다.

완료된 에셋과 버전을 확인한 뒤 **묶음 내보내기**로 실제 이미지·모델 파일과 `manifest.json`을 새 폴더에 저장합니다. 원본과 이전 결과는 유지하고, 상대 경로와 파일별 SHA-256을 기록합니다.

## 현재 확인 범위

- Mac의 Blender 5.2.1 LTS 작업자에서 검·소총·우주선·배럴·바위·나무의 실제 GLB·`.blend`·렌더를 만들고, 별도 Blender 프로세스의 재열기와 독립 파일 검사를 통과했습니다. 이 결과는 작업자와 산출물에 대한 검증입니다.
- Mac 네이티브 백엔드에서 GPT-5.5 구성안과 개별 무기 PNG 5장·GLB 모델 2개의 제작·저장·프로젝트 재열기·독립 내보내기를 통과했습니다. PNG 5장을 직접 열어 각 파일에 무기 하나씩 들어 있음을 확인했습니다. [검증 메타데이터](releases/v0.1.6-game-bundle.json)에 파일별 SHA-256과 확인 범위를 기록합니다.
- 기존 Windows 공개 버전의 네이티브 검증 범위는 [기존 검증 기록](verification.md)을 따릅니다. 브라우저 미리보기와 작업자 직접 실행 결과를 새 게임 묶음의 데스크톱 실행 증거로 확대하지 않습니다.
