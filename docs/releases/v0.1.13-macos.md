# Asset Studio 0.1.13 · Mac 앱과 독립 CLI

Windows 0.1.13이 반영된 master를 받아 Apple Silicon Mac 앱·독립 CLI를 **0.1.13**으로 맞췄습니다. 검증된 원시 3D 캐시, 원격 대기 중 자원 예약 해제, UV·형태를 보존하는 LOD와 별도 미리보기 처리를 같은 소스에서 빌드합니다. Windows 실행 파일·CLI 파일 목록·업데이트 채널의 기존 바이트는 보존합니다.

- [독립 Mac CLI](https://github.com/oocheol/masset/releases/download/v0.1.13/AssetStudioCLI-0.1.13-macos-arm64.zip)
- [Windows·Mac CLI 0.1.13을 고정한 공통 Codex 스킬 ZIP](https://github.com/oocheol/masset/releases/download/v0.1.13/AssetStudio_0.1.13_codex-plugin-windows-macos-cli13.zip)
- [Mac 설치·업데이트 안내](../macos-quickstart.md) · [앱 없는 설치](../skill-first-setup.md) · [배포 메타데이터](v0.1.13-macos.json)

GitHub에 배포한 설치 기능은 **0.1.14**, 실행 도구인 Windows·Mac CLI는 **0.1.13**입니다. 공개 npm 0.1.13은 Mac CLI 0.1.11을 고정하고 있으며 이미 게시한 버전을 교체할 수 없어 새 설치 패키지를 사용합니다. 이전 npm·스킬 ZIP·Mac 0.1.12 앱은 보존하고 새 공통 스킬 ZIP에는 `-cli13` 이름을 사용합니다. 앱에 포함된 설치 버튼도 새 공통 스킬을 등록합니다. npm 레지스트리는 아직 0.1.13이며 0.1.14 게시는 인증 부족으로 대기 중입니다. 설치 안내의 GitHub tarball 명령 또는 새 스킬 ZIP으로 CLI 0.1.13을 바로 사용할 수 있습니다.

## Mac 설치 로더 수정

실제 배포 CLI ZIP을 macOS 기본 도구만 사용하는 로더로 설치하면서 두 문제를 발견했습니다. Foundation의 NSArray에서 꺼낸 NSString을 JXA 문자열로 바꾸지 않아 정상 파일을 없다고 판단했고, arm64에서 variadic `open`의 파일 모드 인수가 전달되지 않아 설치 기록을 다시 읽지 못했습니다. 파일 이름을 명시적으로 변환하고, 프로세스의 제한된 umask 아래 생성한 파일의 소유된 descriptor에 정확한 0600 모드를 설정합니다.

중첩 리소스의 설치·재검사, 0600 설치 기록, 수정된 파일 거부·보존을 실제 macOS 로더 회귀 검사로 확인합니다. 최초 실패의 로더·테스트 로그와 산출물도 별도 출력 폴더에 보존했습니다.

## 검증 범위

배포 기록은 실제 DMG와 업데이트 아카이브의 크기·SHA-256, arm64 앱 버전·ad-hoc 코드 서명, 공통 스킬 포함 여부, 업데이트 서명·인증된 버전·변조 및 버전 재생 거부를 구분합니다. DMG를 마운트하는 설치 스크립트의 `--check-only`는 사용자의 앱을 설치하거나 실행하지 않습니다.

독립 CLI ZIP의 **380개 파일**을 고정 목록의 크기·SHA-256으로 검사하고 새 격리 런타임에 준비합니다. 저장소 밖의 작업 디렉터리에서 네이티브 CLI로 자체 32×24 PNG를 가져와 7×9로 변환하며, 별도 프로세스의 프로젝트 재열기·원본 보존·두 버전·독립 내보내기와 실제 PNG 픽셀 크기를 확인합니다. 사용자 전역 스킬·설치된 앱·원본을 바꾸지 않습니다.

**Mac 잠금 상태에 따라 앱 화면 실행·실제 DMG 설치·기존 앱 업데이트 교체·새 GPT 요청·새 이미지→3D 제작을 생략합니다.** Windows의 3D 속도 및 UV 측정은 [Windows 기록](v0.1.13-windows.md)에 있고 Mac 성능 측정으로 취급하지 않습니다. Apple Developer ID 서명·공증과 Intel Mac 배포는 없습니다. 업데이트의 프로젝트 서명은 Apple 공증과 별개입니다.
