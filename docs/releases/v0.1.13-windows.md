# Asset Studio 0.1.13 · Windows 제작 속도와 3D 품질

Windows 앱·독립 CLI와 공용 npm 스킬을 0.1.13으로 올립니다. 검증된 원시 3D 캐시와 단계별 자원 배분으로 반복 작업을 줄이고, UV·LOD의 품질 검사와 선택 미리보기의 실패 처리를 개선했습니다. 원본과 이전 에셋 버전은 보존합니다.

Mac 앱 **0.1.12**, Apple Silicon 독립 CLI **0.1.11**과 기존 Mac 업데이트 채널을 유지합니다. 이 릴리스에서 Mac 실행 파일을 빌드하지 않았습니다.

## 바뀐 처리 방식

- 공식 Codex 프로세스·연결을 재사용하면서 이미지마다 새 격리 스레드를 만듭니다. 계정·실행 파일·설정 변경, 실패·취소·프로젝트 종료 때 연결을 무효화합니다. 승인한 팔레트·이름·세부 요청을 제작 지시에 유지하고, 일반 이미지는 비율을 보존하며 텍스처는 채우기 방식으로 처리합니다.
- 큐의 SQLite 연결과 문장을 재사용하고 활성 의존 관계만 조회합니다. 원격 이미지 응답을 기다리는 동안 CPU·디스크 예약을 풀고, 결과를 디코딩·저장하기 전에 다시 확보합니다. 계정의 요청 한도와 자원 상한은 유지합니다.
- 입력, 모델·런타임, 전처리, 복원 설정과 작업자 코드를 키로 원시 TripoSR 결과를 캐시합니다. GLB를 실제 다시 열고 크기·해시를 확인한 결과만 사용합니다. 손상 파일은 격리하고 재사용 시 새 추론을 했다고 기록하지 않습니다.
- UV 간격과 작은 메시의 투영 방식을 개선했습니다. 메시 사이의 거리, 세 방향 실루엣과 얇은 부분 손실을 검사해 게임용·LOD 모델을 승인합니다. 안전한 축소가 불가능한 최소 메시의 LOD는 같은 삼각형 수를 유지하고 `reductionApplied=false`를 기록합니다. 게임 모델의 탄젠트 노멀맵을 다른 LOD에 그대로 적용하지 않습니다.
- 모델·텍스처·Blender 원본을 먼저 저장하고 미리보기는 별도 Blender 작업으로 처리합니다. 선택 미리보기 실패나 큐 포화가 완성된 모델을 실패로 바꾸지 않습니다. 늦게 끝난 이전 실행이 새 버전의 상태를 덮어쓰지 못하며, 선택 미리보기만 실행 중이면 완성된 모델을 내보낼 수 있습니다. CLI는 완성 파일을 먼저 저장한 후 선택 미리보기 완료까지 기다립니다.
- Windows Python의 WMI 조회가 불가능할 때도 CPU 종류를 판정할 수 있도록 두 단계의 격리 환경에 운영체제 아키텍처 정보를 유지합니다. 지원하지 않는 CPU는 계속 거절하고 인증 정보·프록시·사용자 Python 경로는 제외합니다.

## 실제 Windows 측정

Shipping CLI를 저장소 밖의 작업 폴더에서 실행했습니다. 기존 준비된 CPython 3.12.10·PyTorch 2.2.2 CPU·고정 TripoSR 모델과 Blender 5.2.1 LTS를 사용했습니다. 새 모델·CUDA·유료 API 다운로드나 새 GPT 요청은 없었습니다.

환경은 i5-12400F, 메모리 64GiB, CPU 스레드 2개입니다. `blue-sphere.png` 한 입력에 `draft`, 512px 텍스처와 게임용 5,000 삼각형 한도를 적용했습니다.

| 구간 | 최초 캐시 없음 | 같은 원시 모델 재사용 |
| --- | ---: | ---: |
| CLI 제작 명령 전체 | 80.904초 | 31.206초 |
| 모델·텍스처 코어 작업 | 69.717초 | 20.390초 |
| 원시 복원 작업 | 48.578초 | 3.531초 |
| 별도 미리보기 작업 | 10.070초 | 9.653초 |

두 결과의 원시 GLB SHA-256은 `0685afab8f4ae7be52cc58f5cb720d21054cd75c14ac514ff6f89ef56c6d27b0`으로 같습니다. 재사용은 추론을 실행하지 않았고 기존 런타임 추론 증거도 그대로였습니다. 원본 파일과 결과 목록의 크기·해시, 별도 프로세스의 프로젝트 재열기·독립 내보내기를 확인했습니다.

같은 원시 메시에서 512px UV 표면 사용률은 이전 보존 결과 **5.74%**에서 새 결과 **25.05%**로 증가했습니다. 새 결과의 겹친 텍셀 비율은 **0.163%**로 기록해 경고하며, 허용 상한을 초과하면 거절합니다. 이는 패딩을 뺀 표면 배치 측정이며 입력 이미지의 해상도나 재구성 모델 자체를 바꾼 결과가 아닙니다.

한 입력의 실제 관측값입니다. 이전 결과는 과거 실행이므로 전체 속도를 직접 통제한 비교로 취급하지 않습니다. CPU·동시 작업·입력 복잡도에 따라 시간과 UV 결과가 달라집니다. 형태 검사는 표본 검사이며 한 장에서 보이지 않는 뒷면의 의미적 정확도, 리깅·쿼드 리토폴로지를 보장하지 않습니다.

코어 전용 검사기는 뒤늦게 추가된 미리보기 파일을 처음에 거절했습니다. 별도 미리보기 영수증으로 실제 scene·5개 이미지·픽셀·안전 실행 필드를 검증하도록 독립 검사기를 보완했습니다. 이 수정으로 런타임 작업자나 기존 산출물을 바꾸지 않았으며, 처음 실패한 기록도 보존했습니다. 영수증을 암호학적 서명으로 취급하지 않습니다.

출시 후보 하나에서 플랫폼 판정이 한 번 실패했습니다. 이후 생성·캐시 작업을 하지 않는 읽기 전용 진단에서 Windows Job Object 안의 두 프로세스는 모두 Windows/AMD64로 확인돼 처음 실패한 정확한 값은 포착하지 못했습니다. 대신 WMI 실패 시 격리 환경의 CPU 정보 누락으로 같은 거절이 발생하는 조건을 재현하고 수정했습니다. 브라우저 검사도 기능 153개 통과 후 Chrome 종료의 기본 10초 제한에서 실패한 기록을 보존했으며, 종료 대기를 45초로 제한한 표준 병렬 검사 전체가 통과했습니다.

## 설치와 플랫폼별 버전

`@oocheol/asset-studio`는 Windows·Mac 공용 npm 패키지 하나입니다. 운영체제에 맞는 네이티브 런타임을 선택하며 npm과 각 플랫폼 CLI의 버전은 독립적으로 관리합니다. 이번 공용 npm 0.1.13은 Windows CLI 0.1.13과 기존 Apple Silicon Mac CLI 0.1.11을 고정합니다. Windows 업데이트가 Mac 런타임을 바꾸지 않습니다.

```sh
npx @oocheol/asset-studio@latest install
npx @oocheol/asset-studio@latest update
```

Codex와 Node.js 22.20 이상이 필요하며 Asset Studio 앱 설치는 선택입니다. 등록 후 새 Codex 작업에서 `$asset-studio`로 요청합니다. 필요한 실행 파일·모델은 출처·크기·해시와 라이선스를 확인하고 승인한 범위에서 준비합니다. [상세 설치 안내](../skill-first-setup.md)를 참고하세요.

기존 Windows 앱은 업데이트 패널에서 0.1.13을 확인해 설치합니다. 업데이트 설치 파일은 기존 키로 서명하며 공개 채널은 버전·크기·SHA-256을 제공합니다. Mac 채널은 기존 0.1.12 내용과 다운로드 주소를 보존합니다.

이번 검증은 새 GPT 계정의 이용 권한·새 라이브 이미지 생성·원격 생성 속도, 기존 사용자 설치의 실제 교체, 클린 Windows 설치를 증명하지 않습니다. Windows Authenticode와 Apple Developer ID 서명·공증은 없습니다. 로컬 산출물·패키지 서명·공개 다운로드·플랫폼 네이티브 실행의 검증 범위는 각각 구분합니다.
